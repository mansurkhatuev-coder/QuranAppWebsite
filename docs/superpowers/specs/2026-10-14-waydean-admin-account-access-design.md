# Вход Waydean через админскую учётную запись

## Цель

Открывать production Waydean preview по той же Supabase Auth учётной записи, что используется в `/admin/`, без суперпароля семейного древа. Preview остаётся доступным только для чтения.

## Выбранная схема

- Экран входа Waydean использует Supabase Auth и ту же конфигурацию проекта, что `/admin/`. Уже существующая сессия переиспользуется; при её отсутствии пользователь может войти email и паролем.
- Email и пароль передаются только напрямую в Supabase Auth по HTTPS через SDK, как в `/admin/`; Edge Function получает только access token. Пароль не передаётся Edge Function, не записывается в URL и не логируется.
- Сервер получает пользователя через Supabase Auth и сравнивает его `user.id` с отдельным серверным значением `WAYDEAN_ADMIN_USER_ID`. Отсутствующая настройка, неверный или истёкший token и несовпадающий ID закрывают доступ.
- Запрос ограничен деревом `drewo`. Проверка выполняется до загрузки `family-tree.json`.
- Кнопка Waydean на production-древе доступна для входа независимо от роли семейной сессии. Серверная проверка, а не видимость кнопки, определяет право открыть preview.
- Текущий вход семьи, суперпароль, роли редактирования и публикация дерева не меняются. Waydean account preview остаётся read-only.
- Выход из preview возвращает на production-древо, не завершая общую Supabase Auth сессию `/admin/`; завершить её можно штатным выходом из `/admin/`.
- Новый ID будет передаваться при серверном deploy из GitHub Actions Secret `WAYDEAN_ADMIN_USER_ID` в одноимённый Supabase Edge Function Secret. Значение не добавляется в исходники и не запрашивается в чате.

## Состояния интерфейса

- Сессия разрешённого аккаунта: открыть дерево.
- Сессии нет: показать вход по email и паролю Supabase.
- Сессия просрочена или проверка не удалась: сохранить введённый email, очистить пароль, показать ошибку и предложить повторный вход.
- Пользователь вошёл, но его ID не разрешён: показать понятное сообщение об отсутствии доступа и не загружать данные древа.
- Сервер недоступен или секрет не настроен: fail closed; показать ошибку с возвратом к текущему древу.

## Границы безопасности

- Не считать любую Supabase-сессию администраторской.
- Не доверять `role`, query string, `localStorage` или другому клиентскому флагу.
- Не переиспользовать общую проверку `requireHubUser` без отдельной проверки ID: у проекта могут быть другие Supabase Auth пользователи.
- Не изменять production пароль, семейные данные, Supabase пользователей или право редактирования дерева.
- Текущий production tree JSON публично обслуживается отдельно; эта схема ограничивает новый интерфейс, а не меняет существующую модель приватности данных.

## Критерии приёмки

1. Разрешённый Supabase user ID проходит проверку и открывает preview.
2. Другой действующий Supabase пользователь получает отказ; дерево до отказа не загружается.
3. Нет сессии, истёкший token, неверный `treeDir`, не настроенный `WAYDEAN_ADMIN_USER_ID` и ошибка API не дают доступа.
4. Повторный вход создаёт обычную Supabase Auth сессию, совместимую с `/admin/`; пароль не попадает в URL или логи.
5. Вход/выход из Waydean не меняет семейный пароль и не включает серверные записи; выход из preview не завершает общую сессию `/admin/`.
6. Действующий старый путь и локальный HOTI preview сохраняют прежнее поведение.

## Выкатка

Сначала реализовать и проверить код локально. Для production потребуются ID пользователя из Supabase Authentication → Users и его настройка в GitHub Actions и Supabase Secrets. Код и Edge Function не выкатывать до отдельного review production-конфигурации; публикация Waydean-кнопки остаётся отдельным релизным шагом.
