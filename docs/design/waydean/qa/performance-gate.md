# Waydean «Древо» — исходная проверка производительности

**Дата:** 2026-09-30<br>
**Статус:** локальная исходная проверка; performance gate не пройден<br>
**Среда:** read-only preview в локальном checkout; production не открывался и не изменялся

## Что проверено

Проверен существующий `drewo/waydean-preview.html` на локальном JSON-дереве. Preview явно сообщает, что данные доступны только для чтения и ничего не сохраняется. Данные наружу не отправлялись.

Локальный набор содержит 157 людей и 14 поколений. В режиме «Все поколения» preview создаёт 157 DOM-карточек и 156 SVG-связей. Геометрия полотна составляет примерно 18 799 × 2 800 CSS px.

В кадре 1440 × 900 полное дерево приходится уменьшать примерно до 2,8%, чтобы уместить его по ширине. При 390 × 844 масштаб после «Подогнать дерево» был около 1,85%. Это не даёт читаемых карточек; обзор должен показывать структуру и выбранный маршрут по правилам LOD, а не миниатюрные полные карточки.

На ширине 390 px исходный preview также показывает пересечения: нижняя панель управления частично закрывает мини-карту, а метка режима попадает поверх 13 карточек. Это baseline существующего read-only preview, не состояние нового desktop prototype. В новом прототипе отдельная проверка 320–1440 px после адаптации профиля и управления не обнаружила пересечений карточек с профилем, мини-картой, меткой режима или кнопками.

Preview сообщает начальное время отрисовки около 393 мс для исходной выборки из пяти карточек. Это собственный таймер текущей страницы; он не измеряет рендер всех 157 людей и не заменяет trace на целевых устройствах.

## Решение по performance gate

**Gate остаётся открытым.** Наличие 157 карточек в локальном DOM подтверждает работу с реальным объёмом данных, но не подтверждает отзывчивость камеры, читаемость на зуме, производительность на слабом телефоне или готовность production.

Перед переходом к реализации на реальных данных нужно:

1. Зафиксировать обзорный LOD без миниатюрных подписей и портретных карточек.
2. Не пересчитывать все связи и координаты на каждом кадре pan/zoom; двигать общее полотно.
3. Проверить скролл/панорамирование, поиск, раскрытие ветви и mini-map на 157 записях.
4. Записать trace High / Medium / Low на целевом desktop и слабом телефоне; отдельно проверить reduced motion.
5. Вернуться к выявленным пересечениям старого read-only preview только при переносе утверждённого Master в реальную страницу. Данные production остаются нетронутыми до отдельного утверждения.
