# Waydean «Древо» — оставшиеся работы до production

**Обновлено:** 2026-10-12.

**Цель:** подготовить новую Waydean как дополнительный премиум-режим действующего продукта. Текущая версия и её функции остаются доступными; данные и backend не переносятся. Для быстрого тестирования пользователь выбрал отдельную кнопку на старом древе, доступную после входа с ролью `super`; она открывает read-only Waydean на данных текущего древа. Публичное включение Premium и любые записи в production остаются отдельными этапами. Платёжный сервис — отдельный будущий этап.
**Текущая стадия:** локальный release-candidate на ветке `codex/waydean-release-candidate`, основанной на `origin/main` (`9a5c224`). Основной экран и печатная студия остаются отдельными маршрутами. Кандидат добавляет кнопку `Waydean · тест`, показывает её только с серверной ролью `super` и повторно подтверждает эту роль при открытии страницы. Изменения пока локальные; production не обновлён. Видео отложено.
**Основание:** WIP-кандидат не закоммичен и не отправлен. Read-only сверка production выполнена частично: публичная страница и заголовки tree JSON endpoint зафиксированы в [live baseline](qa/live-production-baseline-2026-10-10.md); действия, роли, GET-доступ и API-поведение полностью не проверялись. Подписка push может менять только файл подписок и только после явного действия пользователя в проверенном account-маршруте; local preview не вызывает production API. Ничего не pushed и не deployed.

[Общая спецификация](product-design-spec.md) определяет требования. Этот документ определяет **очередь оставшихся работ и условия завершения**. Подробные правила находятся в Design Bible, Masters, Motion/Print/Video Design Systems; результаты проверок — в `qa/`. При изменении статуса обновлять эту очередь и соответствующий отчёт, чтобы старые README не становились отдельным планом.

## 0. Продуктовое решение: Waydean как премиум-режим

Пользователь утвердил additive-модель: Waydean становится отдельным новым режимом внутри текущего продукта. Это не замена всей бесплатной версии и не новый продукт с отдельными семейными данными.

- **Текущая версия остаётся рабочей:** старый экран, обычный вход и подтверждённые возможности не удалять. Для аккаунта без права на новый режим продолжает открываться текущий сценарий.
- **Общие данные и сервисы:** Waydean подключается к тому же дереву, API, сессии, журналу и хранилищу фотографий через один адаптер. Отдельную базу или копию семейного дерева не создавать.
- **Админский тест до платежей:** отдельная кнопка показывается только для серверно подтверждённой роли `super`; тестовый маршрут повторно проверяет подписанную сессию через существующее действие `auth`. Ссылка, query-параметр и клиентская видимость сами по себе не дают доступ. Текущий тестовый экран читает древо и не сохраняет правки.
- **Кнопка Premium:** сначала сверить её смысл и поведение в реально развёрнутом интерфейсе. В текущем checkout `drewo/index.html` слово Premium обозначает визуальную тему («Классика / Премиум»), а не подтверждённую подписку или переход в новую версию. Не превращать переключатель темы в гейт доступа вслепую. Если live-кнопка действительно служит входом в Premium, подключить к ней Waydean для разрешённого аккаунта; иначе добавить отдельный пункт запуска, сохранив настройку темы.
- **Платёжная система позже:** будущий провайдер только выдаёт/отзывает entitlement на сервере. Waydean проверяет единый статус доступа и не зависит от конкретного провайдера, checkout SDK или клиентского флага.
- **Безопасный отказ и возврат:** отсутствие/истечение права не блокирует текущее древо; feature flag и fallback открывают старую версию. Отключение Waydean не меняет семейные данные и не требует миграции назад.

**Live-проверка 2026-10-10:** доставленная шапка содержит “Премиум” в селекторе оформления (“Классика / Премиум”), а не подтверждённый вход в новую версию. Анонимный HEAD дерева JSON ответил `200 application/json`; тело не загружалось. Это частичная baseline-проверка и блокирует подключение нового UI к production-данным до подтверждения ожидаемой модели доступа.

**Порядок:** локально подготовить основной экран и взаимодействия → опубликовать отдельную admin-only read-only точку входа на старом древе → дать владельцу проверить реальную версию → исправлять замечания в локальном кандидате → отдельно согласовать production-запись/публичный Premium → подключить платежи отдельным решением в будущем.

**Вне текущего этапа:** реальное производство entitlement, production deployment, подключение checkout/платёжного провайдера и миграция любых данных.

**Наблюдение по управлению древом (2026-10-10):** в локальном исходнике уже есть drag-to-pan, zoom колесом/щипком вокруг указателя, виртуальное поле вокруг увеличенного древа, запрет выделения текста на полотне и кнопка «Показать всё дерево». Выбор человека в режиме `all-tree` меняет выбранную запись, но не сужает набор; отдельная кнопка «Показать ветвь» переключает режим явно. В этой итерации центр выбранной карточки выравнивается по центру области просмотра, максимальный zoom поднят до 240%, а desktop больше не переходит в LOD-состояние, скрывающее аватары. Это подтверждено только чтением исходника; локальный браузерный review остаётся открытым. Не считать пользовательские жалобы закрытыми до ручного review.

**Новое направление 2026-10-12:** пользователь поручил перенести в Waydean все функции текущего продукта, сохраняя старый экран как рабочий вариант и сначала собирая безопасную локальную копию для самостоятельного тестирования. Локальный сценарий включает изменение данных человека и тейпа, добавление/перенос/удаление листовой связи, фото в IndexedDB, Print Studio для сохранённой копии, журнал локальных операций, автоматические/ручные снимки, закрепление и восстановление с резервированием текущего состояния. Фотофайлы в локальных снимках не сохраняются. Это не подключает запись дерева в production. Локальная PWA-установка, offline cache, тестовое уведомление и защищённые account-маршрутом push subscribe/unsubscribe добавлены; последний пишет только подписку устройства после явного подтверждения. Локально перенесены выбор «Кто я», отметка карточки и показ пути от предков; это только предпочтение браузера и не меняет данные древа. Серверные авторизация/сохранение дерева, журнал, merge конфликтов, backups/restore и административные блокировки остаются открытыми. Полный инвентарь находится в [production parity matrix](qa/production-feature-parity.md#полный-перечень-функций-и-серверных-операций-источника). Видео остаётся отложенным, как пользователь решил ранее. Проверки на этом проходе отложены по просьбе пользователя; новый код ещё не runtime-проверен.

**Правило полноты функций:** до снятия любого legacy-входа каждая применимая пользовательская функция и серверное действие должны быть отмечены в [полной матрице production parity](qa/production-feature-parity.md#полный-перечень-функций-и-серверных-операций-источника) как «перенесено», «оставлено на прежнем маршруте» или «новая функция». Внешний кабинет `trees/` (создание/архивирование дерева, реквизиты, оплата) остаётся доступен на прежнем маршруте. Эта инвентаризация по исходникам пока не подтверждает, что все действия включены в live production.

Локальный запуск восстановлен: причина была в отсутствующей отметке `waydean-local-build` в preview HTML, которую ожидает startup script. После её добавления `scripts/start-waydean-local.ps1 -NoBrowser` подтвердил сборку и сообщил URL `http://127.0.0.1:8784/drewo/waydean-preview.html?state=all-tree`. Это подтверждает запуск локального сервера, но не поведение интерфейса.

**Локальное открытие 2026-10-10:** повторная загрузка дерева падала уже после получения HOTI JSON: обработчик ссылался на удалённый `#morePrint`, а в меню осталась кнопка `#moreExport`. Ссылка исправлена; скрипт и CSS получили cache keys `main-20` и `layout.css?v=6`. JS синтаксически корректен, все 74 буквальных ID-селектора найдены в HTML, preview/JS/JSON отвечают локально, HOTI-модель разбирается в 157 человек и 14 поколений. В ответ на прошлые замечания профиль теперь закрывается направляющей кнопкой с увеличенной мобильной зоной нажатия; одновременное скрытие боковой панели и профиля убирает обе колонки полностью. Визуальную загрузку после исправления и новые состояния панелей нужно подтвердить в окне пользователя.

**Локальные действия 2026-10-10:** кнопка «Поделиться» в локальном preview больше не выглядит как неработающая: она копирует ссылку текущего состояния и прямо сообщает, что адрес доступен только при запущенном preview-сервере на этом компьютере. Производственный обработчик в `drewo/index.html` не менялся. Экспорт ведёт в отдельную печатную мастерскую, видео — в отдельный кинематографичный прототип; оба доступны из «Ещё» и локально не подменяют production-потоки.

**Отдаление и даты 2026-10-10:** причиной пустых мелких карточек на desktop было принудительное удержание уровня `compact`, даже когда ширина карточки при 25% уже требовала общего обзора. Desktop теперь переходит в штатный `overview`: имена не превращаются в почти нечитаемые пиксели, выбранный человек остаётся яркой точкой, а подпись объясняет, что нужно приблизить для чтения имён. Имена в обычном масштабе переведены с Georgia на чёткий системный UI-шрифт. В карточки добавлены григорианский/приближённый хиджрийский годы с тем же расчётом production и плавной сменой раз в 3 секунды. В HOTI JSON есть даты только у 12 из 157 людей; исходные данные не изменялись. Изменения ещё требуют визуального review в браузере.

**Обзор дерева 2026-10-10:** размер точек и связей теперь компенсируется относительно текущего масштаба, поэтому обзор не превращается в россыпь едва заметных пикселей; фоновые связи приглушены, а путь выбранного человека остаётся заметным. Это локальная правка CSS/JS; визуальная приёмка в браузере всё ещё нужна.

**Продолжение локальной доводки 2026-10-11:** увеличен предел масштаба с 240% до 320%; на мобильном отложено скрытие портретов и подписей (detail → compact: 58 px вместо 82 px; compact → overview: 34 px вместо 56 px), а на desktop карточки остаются в полном виде. При выборе человека в полном дереве камера больше не поднимает масштаб принудительно до 90%, а сохраняет выбранный пользователем уровень. На локальном HOTI-preview визуально подтверждены 157 записей / 14 поколений и видимые силуэты на узком экране; на desktop при 1280 × 800 подтверждено полное оформление карточек и освобождение области древа при сворачивании профиля. Код и preview остаются локальными; сценарии и полный suite отложены по просьбе пользователя.

**Возврат ко всему дереву 2026-10-10:** верхняя/мобильная кнопка «Древо» и пункты «Все поколения»/«Показать всё дерево» теперь возвращают полный обзор и сбрасывают активные фильтры. Это исправляет незаметное сужение дерева до ближайших поколений при возврате через основную навигацию. Изменение пока локальное; тестовые сценарии отложены по просьбе пользователя.

**Найдено при открытии узкого экрана 2026-10-10:** на viewport 451 × 672 локальный HOTI-набор загружается (157 карточек есть в DOM/доступности), но дерево, мини-карта и камера не видны на снимке. Нажатие «Вписать» и одно уменьшение масштаба картину не изменили. Причина пока не установлена; мобильное полотно не считать принятым и разобраться с геометрией/слоями в следующем проходе. Полные сценарии не запускались.

## 2. Условия, которые сохраняем

- Сначала локальная работа, затем изолированный staging, затем production после явного утверждения проверенного результата.
- Все подтверждённые действующие функции сохраняются. Список из локального checkout сначала сверяется с реально развёрнутой версией; неподтверждённая возможность не объявляется production baseline.
- Следующий **визуальный** блок начинается только после совпадения предыдущего с его утверждённым Master Reference. Уже начатые блоки нужно довести до приёмки; новые эффекты и шаблоны не расширяют очередь.
- Если фото нет — нейтральный силуэт головы и плеч без лица, глаз, носа и рта. Не выдумывать даты и портреты.
- HOTI используется локально для проверки масштаба. Синтетические fixtures, публичные документы и QA-логи не пополняются семейными именами, фото и сырым JSON.
- Локальный Pages-кандидат формирует отдельный artifact: production `drewo/` и `t/hoti/` сохраняются, synthetic preview получает только `fixtures/prototype-people.mjs`, доступна synthetic Print Studio с demo-портретами; полный fixture, тестовые файлы, HOTI-прототип/данные и видео-экспорт исключены. HOTI в браузере загружается только на loopback. Эти фильтры пока только в рабочем дереве и не действуют в GitHub Actions, пока кандидат не пройдёт release-процесс.
- **PNG как формат печатного экспорта пропущен по решению пользователя.** Screenshot/pixel review остаётся в плане качества.
- Видео — самостоятельная сборка из шаблона; тяжёлый рендер выполняется вне телефона. Печать, видео и движение экранного дерева имеют отдельные проверки.
- Локальные bundle, профили браузера и рендеры размещать в `H:\CodexBuildTemp\WaydeanRemotion`; использовать `WAYDEAN_EXPORT_TEMP_DIR`, `TEMP`, `TMP`, `TMPDIR`. Существующие артефакты не удалять ради нового запуска.
- Пользователя не останавливать ради обычных обратимых исправлений. Показывать законченный пакет; решения о смене Master, сокращении объёма, платной инфраструктуре и production остаются явными решениями.
