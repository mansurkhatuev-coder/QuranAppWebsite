# Waydean «Древо» — каталог экранных состояний

**Версия:** 0.1  
**Статус:** набор для первого локального prototype  
**Основа:** [Component Bible](../components/component-bible.md), [Desktop Master](../masters/desktop-master.md), [Mobile Master](../masters/mobile-master.md)  
**Условия проверки:** mobile 390 × 844 CSS px; desktop 1440 × 900 CSS px

Этот каталог задаёт кадры, которые нужно показать и проверить до реализации визуальных блоков в `drewo/`. Все записи в первом prototype вымышлены. Текущий mobile prototype демонстрирует интерактивные состояния на 12 фиктивных людях; это локальная дизайн-песочница, не рабочая версия сайта.

## 3. Данные prototype

- Ровно 12 фиктивных записей, в том числе два человека с именем «Магомед», длинное имя и неизвестные даты.
- У каждого человека заданы только поля, нужные для кадра: ID, имя, годы, поколение, родитель, принадлежность к выбранной ветви, признак фото.
- Фотографий в наборе нет, поэтому везде отображается один и тот же нейтральный безликий силуэт.
- Цифры статистики, результаты фильтра и результаты поиска считаются из этого набора, а не прописаны отдельно в разметке.
- Набор не содержит реальных персональных сведений и не подключён к Supabase или API проекта.

## 4. Порядок review

1. Сначала кадры M01–M12 в одном mobile prototype.
2. Исправить подтверждённые расхождения с Mobile Master и Component Bible.
3. Сохранить итоговые скриншоты и ссылки на эталоны в [каталоге prototype](../prototype/README.md).
4. Mobile-состояния M01–M12 приняты; текущий этап — review D01–D06 в [desktop prototype](../desktop-prototype/README.md).
5. Статические Masters приняты; движение не используется для маскировки проблем макета. Правила следующего этапа см. в [Motion Bible](../motion/motion-bible.md).
6. После принятия static Masters перенести визуальный слой в `drewo/` на отдельной локальной ветке; production остаётся заблокирован до отдельного утверждения.

## 5. Границы текущего набора

Prototype проверяет композицию, тексты, локальные переходы, пустые состояния и логику выбранного человека на фиктивных данных. Он не проверяет реальные права доступа, серверное поведение, работу Supabase, большие данные или производительность сайта. Эти проверки остаются отдельными этапами плана.


## 6. Локальный просмотр на реальных данных — принят для перехода дальше

Изолированная read-only страница `drewo/waydean-preview.html` проверяет принятую композицию на локальном `family-tree.json`. Она не заменяет редактор `drewo/index.html`, не сохраняет изменения и не подключается к Supabase. Этот этап остаётся локальным и не опубликован.

| Проверка | Наблюдение |
| --- | --- |
| Локальный набор | 157 записей, 14 поколений; один локальный thumbnail с фото. |
| Desktop, 1440 × 900 | Стартовый семейный контекст — 5 узлов; профиль и выбранный узел синхронны; переполнений текста в карточках нет. |
| Mobile, 390 × 844 | Стартовый семейный контекст — 5 узлов; нижняя навигация и профиль доступны; горизонтального расширения страницы и переполнений текста нет. |
| Все поколения | Все 157 узлов создаются; полотно около 18,8 тыс. CSS px шириной до масштабирования. Для обзора используется «Подогнать дерево». |
| Локальная производительность | Initial DOM render: 42–52 мс при 5 узлах в трёх прогонах. Перерисовка режима всех поколений: 14,5–22,6 мс при 157 узлах в пяти прогонах на desktop Edge. Это синхронные локальные замеры, не benchmark телефона и не обещание FPS. |
| Основные взаимодействия | Поиск возвращает совпадения; выбор результата обновляет выбранный профиль; режим полного дерева рендерит 157 узлов. |
| Сеть и ошибки | Запросы данных/ресурсов в прогоне обслуживались только локальным `127.0.0.1`; JavaScript page errors — 0. |
| Фото и пустой профиль | Единственная запись с фото запрашивает только локальный thumbnail. Для других записей используется нейтральный силуэт головы и плеч без лица. |

Скриншоты реальных данных сохранены только локально в папке результатов задачи и не добавляются в Git. Имена и фотографии из семейного набора не копируются в документацию или ветку.

**Статус:** после исправления переполнения текста пользователь попросил идти дальше; local review принят как основание для следующего этапа. Preview и его кадры остаются локальными. Замеры не закрывают performance gate на целевом телефоне и не разрешают production-публикацию.
