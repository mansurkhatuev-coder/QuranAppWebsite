# Waydean «Древо» — каталог экранных состояний

**Версия:** 0.1  
**Статус:** набор для первого локального prototype  
**Основа:** [Component Bible](../components/component-bible.md), [Desktop Master](../masters/desktop-master.md), [Mobile Master](../masters/mobile-master.md)  
**Условия проверки:** mobile 390 × 844 CSS px; desktop 1440 × 900 CSS px

Этот каталог задаёт кадры, которые нужно показать и проверить до реализации визуальных блоков в `drewo/`. Все записи в первом prototype вымышлены. Текущий mobile prototype демонстрирует интерактивные состояния на 12 фиктивных людях; это локальная дизайн-песочница, не рабочая версия сайта.

## 3. Данные prototype

- Ровно 12 фиктивных записей, в том числе два человека с именем «Магомед», длинное имя и неизвестные даты.
- У каждого человека заданы только поля, нужные для кадра: ID, имя, годы, поколение, родитель, принадлежность к выбранной ветви, признак фото.
- Фотографий в наборе нет, поэтому везде отображается один и тот же нейтральный безликий силуэт.
- Цифры статистики, результаты фильтра и результаты поиска считаются из этого набора, а не прописаны отдельно в разметке.
- Набор не содержит реальных персональных сведений и не подключён к Supabase или API проекта.

## 4. Порядок review

1. Сначала кадры M01–M12 в одном mobile prototype.
2. Исправить подтверждённые расхождения с Mobile Master и Component Bible.
3. Сохранить итоговые скриншоты и ссылки на эталоны в [каталоге prototype](../prototype/README.md).
4. Mobile-состояния M01–M12 приняты; текущий этап — review D01–D06 в [desktop prototype](../desktop-prototype/README.md).
5. Только после статических состояний описывать/добавлять motion; движение не используется для маскировки проблем макета.
6. После принятия static Masters перенести визуальный слой в `drewo/` на отдельной локальной ветке; production остаётся заблокирован до отдельного утверждения.

## 5. Границы текущего набора

Prototype проверяет композицию, тексты, локальные переходы, пустые состояния и логику выбранного человека на фиктивных данных. Он не проверяет реальные права доступа, серверное поведение, работу Supabase, большие данные или производительность сайта. Эти проверки остаются отдельными этапами плана.
