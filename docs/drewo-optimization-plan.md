# План древ (халява, без VPN на просмотр)

Ревью 17.08.2026: старая версия этого файла предлагала Beget/VPS и «телефон больше не видит Cloudflare». Это **отклонено**: только бесплатное, VPN допускается лишь на «Сохранить». Ниже — согласованный план.

Сайт и будущее приложение читают одно и то же. Сайты не убираем.

---

## Что верно из диагностики (оставить)

Виновник входа и фото — **Cloudflare на `*.supabase.co`**, не `waydean.ru`.

| Хост | Кто | Cloudflare |
|---|---|---|
| `waydean.ru/drewo/` | GitHub Pages + Fastly | нет |
| вход / сохранение / онлайн | Supabase Edge Function | да (`cf-ray`, `__cf_bm`) |
| фото | Supabase Storage | да |
| Cloudflare Pages | выключен | не в пути |

Без VPN открывается HTML, не доходят вход и кружки. С VPN Cloudflare часто вешает `fetch` (challenge / HTTP/3) — кажется, что «сайт не открылся».

Не делать: оранжевое облако на `waydean.ru`, Worker как `qf-proxy` для древ, платный хостинг, прокси nginx/Beget.

## Цель на сейчас (не «всё без VPN»)

| Действие | Без VPN | С VPN |
|---|---|---|
| Открыть древо, войти, видеть уже залитые фото | да | да |
| Онлайн / визиты | можно скрыть | как сейчас |
| «Сохранить», новое фото на сайт, бэкапы | нет, копится в браузере | да |

Жонглирование «VPN чтобы войти, выключить чтобы открыть» уходит. VPN — только отправка.

## Сделать (бесплатно, уже есть GitHub + Supabase)

1. **Вход локально.** Пароль семьи сверять с хешем в `access.json` (поле уже есть) или с запасным совпадением на клиенте. **Не оставлять** `гуно` / `баташ` / `демо` открытым текстом в HTML. Суперпароль — только сервер (редко, с VPN).
2. **Фото смотреть с Pages.** Кладём сжатые `id-thumb.jpg` + `id.jpg` (~800px) в `drewo/photos/` и аналоги. `PHOTO_PUBLIC_BASE` — относительный путь, не `supabase.co`. Оригиналы с камеры в git не класть. Старые снимки один раз перенести из Storage.
3. **Новое фото** сначала в браузере; на GitHub уезжает вместе с «Сохранить» (пока с VPN). Иначе человек думает, что фото уже у всех.
4. **Визиты не коммитить.** Счётчик и онлайн уже в `drewo_tree_stats` / `drewo_presence`. Убрать запись `access.json` на каждый заход — иначе лимит ~10 деплоев Pages/час.
5. **Таймаут `callPublishApi` ~12 с.** Не крутить «Проверяем…» вечно. Просмотр дерева не зависит от Supabase.
6. **Двое жмут «Сохранить»:** на сервер — пачка операций по `id` (`add` / `rename` / `year` / `photo`…), накатывать на одно дерево. Разные люди — оба изменения без окон. Одно поле одного человека — чья позже, та и цифра. Очередь GitHub **не** заменяет слияние: она только не даёт двум коммитам сломать ветку. Текущий activity-лог для этого недостаточен — нужна явная пачка ops.
7. **Не бэкапить целый `index.html`.** Только JSON дерева.

## Риски (приняты)

- GitHub не забьётся на ~365 людей, если только сжатые jpeg и без визитов в git. Раздувает история пересъёмок и HTML-бэкапы.
- Репозиторий публичный: имена, годы, фото видны по URL; git помнит удалённое. Это уже так со Storage.
- После сохранения остальные могут ~10 мин видеть старое (кэш Pages).
- Сам GitHub в РФ иногда не открывается — без второго халявного хостинга не лечится.
- Онлайн/визиты без VPN не появятся — не блокировать из-за этого вход.

## Потом (сайт + приложение)

Один `drewo.js` на три страницы, данные из `family-tree.json`, не дублировать JSON в HTML. Приложение читает те же JSON и `/photos/`, пишет тем же журналом операций. Не оборачивать текущий сайт как есть — унаследует Cloudflare.

Шрифты с Google и jsdelivr у `/trees/` — по возможности свои файлы (бесплатно), не обязательно в первом заходе.
