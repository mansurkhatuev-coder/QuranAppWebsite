# План древ (халява, без VPN на просмотр)

Ревью 17.08.2026: старая версия этого файла предлагала Beget/VPS и «телефон больше не видит Cloudflare». Это **отклонено**: только бесплатное, VPN допускается лишь на «Сохранить». Ниже — согласованный план.

Сайт и будущее приложение читают одно и то же. Сайты не убираем.

---

## Что верно из диагностики (оставить)

Виновник входа и фото — **Cloudflare на `*.supabase.co`**, не `waydean.ru`.

| Хост | Кто | Cloudflare |
|---|---|---|
| `waydean.ru/drewo/` | GitHub Pages + Fastly | нет |
| вход / сохранение / онлайн | Supabase Edge Function | да (`cf-ray`, `__cf_bm`) |
| фото | Supabase Storage | да |
| Cloudflare Pages | выключен | не в пути |

Без VPN открывается HTML, не доходят вход и кружки. С VPN Cloudflare часто вешает `fetch` (challenge / HTTP/3) — кажется, что «сайт не открылся».

Не делать: оранжевое облако на `waydean.ru`, Worker как `qf-proxy` для древ, платный хостинг, прокси nginx/Beget.

---

## Цель на сейчас (не «всё без VPN»)

| Действие | Без VPN | С VPN |
|---|---|---|
| Открыть древо, войти, видеть уже залитые фото | да | да |
| «Сохранить», новое фото на сайт, бэкапы | нет, копится в браузере | да |

Жонглирование «VPN чтобы войти, выключить чтобы открыть» уходит. VPN — только отправка.

## Сделать (бесплатно, уже есть GitHub + Supabase)

1. **Вход локально.** Пароль семьи сверять с хешем в `access.json` (поле уже есть) или с запасным совпадением на клиенте. **Не оставлять** `гуно` / `баташ` / `демо` открытым текстом в HTML. Суперпароль — только сервер (редко, с VPN).
2. **Фото смотреть с Pages.** Кладём сжатые `id-thumb.jpg` + `id.jpg` (~800px) в `drewo/photos/` и аналоги. `PHOTO_PUBLIC_BASE` — относительный путь, не `supabase.co`. Оригиналы с камеры в git не класть. Старые снимки один раз перенести из Storage.
3. **Новое фото** сначала в браузере; на GitHub уезжает вместе с «Сохранить» (пока с VPN). Иначе человек думает, что фото уже у всех.
4. **Счётчик визитов и онлайн убрать.** Не писать в git и не дергать Supabase ради цифр. Плашки на древе и в `/trees/` нет.
5. **Таймаут `callPublishApi` ~12 с.** Не крутить «Проверяем…» вечно. Просмотр дерева не зависит от Supabase.
6. **Двое жмут «Сохранить»:** трёхстороннее слияние по `id` (снимок при загрузке + локальное + сервер). Разные люди — оба изменения без окон. Одно поле одного человека — чья позже, та и цифра. Удаление и перенос отца не сливаются автоматически. Очередь GitHub **не** заменяет слияние: она только не даёт двум коммитам сломать ветку.
7. **Не бэкапить целый `index.html`.** Только JSON дерева.

## Риски (приняты)

- GitHub не забьётся на ~365 людей, если только сжатые jpeg и без визитов в git. Раздувает история пересъёмок и HTML-бэкапы.
- Репозиторий публичный: имена, годы, фото видны по URL; git помнит удалённое. Это уже так со Storage.
- После сохранения остальные могут ~10 мин видеть старое (кэш Pages).
- Сам GitHub в РФ иногда не открывается — без второго халявного хостинга не лечится.
- Онлайн/визиты без VPN не появятся — не блокировать из-за этого вход.

## Потом (сайт + приложение)

Один `drewo.js` на три страницы, данные из `family-tree.json`, не дублировать JSON в HTML. Приложение читает те же JSON и `/photos/`. Не оборачивать текущий сайт как есть — унаследует Cloudflare.

Шрифты с Google и jsdelivr у `/trees/` — по возможности свои файлы (бесплатно), не обязательно в первом заходе.

## Порядок

1. **Сделано:** таймаут 12 с, вход по хешу, фото Мансура на Pages, на просмотре нет visit/presence.
2. **Сделано:** новые фото копятся в IndexedDB и уезжают в `*/photos/*.jpg` одним коммитом с «Сохранить» (base64). Storage больше не используется. Нужен деплой `publish-drewo`.
3. **Сделано в коде:** тихое слияние при двух «Сохранить». Сервер (и клиент, если функция ещё старая) делает трёхстороннее слияние по `id`: чужие поля остаются, свои накатываются; одно поле — чья запись позже. Удаление и перенос отца не сливаются. Окон выбора нет. Нужен деплой `publish-drewo`.
4. **Сделано:** счётчик визитов и «онлайн» сняты с древ и с `/trees/`. Функция больше не считает заходы.
5. Вынести общий JS, когда дойдёте до приложения.

Критерий: с телефона без VPN открыть, войти, увидеть фото; с VPN — отправить правки; в DevTools на просмотре нет `supabase.co`.

## Ревью плана (17.08, повторно)

Цель и диагноз верные. Ниже — дыры, из‑за которых «как написано» ещё нельзя считать готовым ТЗ.

**Противоречие во входе.** Закрыто в этом PR: в `access.json` записан SHA-256 (`drewo-pw:` + пароль), клиент считает тот же хеш. Текста `гуно` / `баташ` в HTML семьи нет (в демо пароль `демо` по-прежнему на экране входа — так задумано).

**Пункт 6.** Закрыто трёхсторонним слиянием снимков (`baseTreeJson` + текущее + сервер), без отдельной пачки ops. Удаление/перенос по-прежнему не автосливаются.

**Фото в git.** Закрыто в этом PR: jpeg пишутся как `encoding: 'base64'`, очередь в IndexedDB, не в `localStorage`.

**Счётчик.** Снят: нет плашки на древе, нет визитов/онлайна в `/trees/`, `record-visit` / presence на сервере игнорируются. `status` остаётся только для блокировки правок.

**Три `index.html`.** Пока нет общего `drewo.js`, любой пункт надо повторить в drewo / dada-yurt / reklama. В плане это отодвинуто в «потом», а правки 1–5 как раз сейчас — риск, что одно древо останется на Cloudflare-фото.

**Итог ревью:** план как направление — ок. Первый кусок (вход, фото, визиты) и тихое слияние — в коде. Осталось вынести общий JS. Очередь коммитов не делать, пока сохранения редкие. Деплой `publish-drewo` обязателен: без него фото в git и слияние на сервере не включатся; клиент тогда сам сольёт по 409.
