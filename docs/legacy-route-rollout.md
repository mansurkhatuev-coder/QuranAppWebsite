# Переход старых ссылок «Древа»

Семейные адреса остаются на старом сайте, пока конкретный маршрут не принят к переносу. Состояния задаются в `scripts/legacy-transitions.json`; сейчас `routes` пуст, поэтому сборка не заменяет ни одну старую страницу.

Для принятого переноса указываются только известные каталоги семей. `transferring` заменяет старую страницу коротким сообщением и закрывает доступ к старым ресурсам внутри публикационного артефакта. `migrated` публикует фиксированный переход на `/t/<tree-id>/` нового HTTPS origin. Новый UUID нельзя брать из URL-запроса. Сборка проверяет каталог и UUID по allowlist, очищает бывшие файлы семейной страницы и затем повторно проверяет публичный артефакт. Сам манифест переходов не попадает в публикацию.

Перед изменением маршрута необходимо подтвердить владельца и участников, остановить запись, сделать приватный снимок, перенести и сверить дерево, вложения и тариф, проверить новый вход и приглашения, затем проверить старый и новый хост без сессии и обновление PWA. Семьи переключаются по одной. Если любой gate не пройден, запись остаётся на текущем источнике, а маршрут остаётся прежним.

Оба Pages workflow — основной и keepalive — запускают один sanitizing builder и публикуют только `dist/pages`. Keepalive больше не публикует корень репозитория. Локальные синтетические проверки:

```powershell
node --test scripts/prepare-pages-artifact.test.mjs scripts/legacy-route-transitions.test.mjs
```

Само изменение `scripts/legacy-transitions.json` не выполняет перенос, не публикует новый код и не включает запись на новом хосте. Публикация всё равно проходит через утверждённый release gate.
