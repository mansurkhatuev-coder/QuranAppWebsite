# Переход старых ссылок «Древа»

Семейные адреса остаются на старом сайте, пока конкретный маршрут не принят к переносу. Состояния задаются в `scripts/legacy-transitions.json`; сейчас `routes` пуст, поэтому сборка не заменяет ни одну старую страницу.

`replaceNekLanding` управляет отдельно переходом с `/nek/` на Atlas нового приложения. Значение `false` оставляет прежнюю главную страницу. При `true` только заход без параметров и фрагмента открывает новый Atlas. Сохранённые ссылки `/nek/?login=1` и `/nek/?login=1&u=<логин>` открывают прежнюю форму. После успешного семейного входа сессия сохраняется во вкладке и открывается проверенный адрес старого древа. Перенесённый адрес ведёт к личному входу Drewo, где роль подтверждается новым сервером.

Для утверждённого переноса указываются только известные каталоги семей. `frozen` блокирует запись через Edge Function и оставляет старую страницу открытой для чтения. `transferring` сохраняет запрет записи и заменяет страницу сообщением о переносе. `migrated` сохраняет запрет записи и ведёт на `/t/<tree-id>/` нового HTTPS origin. Новый UUID берётся из манифеста выпуска. Сборка проверяет каталог и UUID, убирает бывшие файлы семейной страницы для `transferring` и `migrated` и проверяет публичный артефакт. Сам манифест переходов остаётся внутри процесса выпуска.

При переносе основного `/drewo/` сборка оставляет по прежним адресам утверждённые общие скрипты, стили, изображения и оболочку Waydean. Их используют остальные древа, демо, Некъ и кабинет. Существующий `legacy.html` получает ту же страницу перехода, что и прямой адрес семьи. При открытии выведенной семьи из общего просмотра переход идёт через старый адрес семьи без параметров и фрагмента. Для других семей и демо общий просмотр загружается как обычно.

Перед включением первой заморозки версия Edge Function с проверкой записи должна быть развёрнута. Пустой манифест должен присутствовать в рабочей ветке до выпуска этой функции. Если файл пропал, повреждён или недоступен, API отказывает в записи. Проверить работу на отдельном тестовом проекте, где нет реальных семейных данных.

Для конкретной семьи сначала записать `frozen` в рабочую ветку и зафиксировать SHA коммита. Он включает сохранения, успевшие попасть в ветку до заморозки. Edge проверяет манифест на том же коммите, который служит родителем записи. Обновление ссылки Git выполняется без force, поэтому подготовленная ранее попытка сохранения отклоняется, если ветка успела измениться. На время заморозки остановить прямые изменения семейных файлов и сторонние инструменты записи в репозиторий. Серверная проверка действует на записи через Edge Function. [Правила обновления ссылок GitHub](https://docs.github.com/en/rest/git/refs#update-a-reference).

После подтверждения запрета записи создать приватный снимок по зафиксированному SHA. Сверить владельца, участников, дерево, вложения и тариф. Проверить новый вход, приглашения, ссылки без сессии, очистку CDN и обновление PWA перед открытием записи в новом приложении. При откате снять блокировку старого древа только после сверки правок, принятых новой системой.

Оба Pages workflow — основной и keepalive — запускают один sanitizing builder и публикуют только `dist/pages`. Keepalive больше не публикует корень репозитория. Локальные синтетические проверки:

```powershell
node --test scripts/prepare-pages-artifact.test.mjs scripts/legacy-route-transitions.test.mjs
```

Перед выпуском Edge Function подтвердить список действующих операторов кабинета. `DREWO_HUB_USER_IDS` принимает UUID аккаунтов Supabase через запятую. Пустой или ошибочный список закрывает обзор, работу с данными доступа, создание древ и управление оплатой. После настройки проверить вход разрешённого оператора и отказ для обычного аккаунта. Публичный статус древа возвращает только признак блокировки и общее сообщение. Семейные сессии и отдельный вход администратора Waydean используют свои прежние проверки.

Само изменение `scripts/legacy-transitions.json` не выполняет перенос, не публикует новый код и не включает запись на новом хосте. Публикация всё равно проходит через утверждённый release gate.
