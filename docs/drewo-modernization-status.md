# «Древо»: единая цель и готовность к публикации

Обновлено 2026-11-28. Сверено с исходным ТЗ из файла пользователя, общей ссылкой на чат, текущей веткой `motion-polish-20261124`, PR #262 и объединённым в эту ветку PR #263. Пользователь выбрал бесплатный выпуск напрямую в production без отдельной тестовой среды; для Supabase leaked-password protection принято исключение по бесплатному плану.

## Цель

Завершить модернизацию всей генеалогической платформы: сохранить интерактивный 3D-атлас главным экраном, объединить его с семейными и личными древами, довести единый дизайн и редактор, сделать статистику честной, защитить семейные данные, сохранить старые ссылки и подготовить публикацию с проверяемым порядком действий и откатом. Саморегистрация — одна из функций, а не цель проекта.

PR #263 был слит в `motion-polish-20261124` коммитом `144d3d04`; этот коммит входит в текущую ветку PR #262. В него вошли усиленная авторизация управляющего, серверные метрики кабинета, очистка PWA-кэша от частных снимков и выдача семейных фотографий через серверную проверку сессии.

## Уже реализовано

- `/atlas/` — точка входа с четырьмя действиями: создать древо, войти, посмотреть демо, исследовать атлас. Трёхмерная карта остаётся центральной функцией. `/nek/`, `/t/` и приглашения ведут в совместимый поток.
- Личный пользователь регистрируется, подтверждает почту и может один раз создать древо без обязательного знания тухума, тейпа или селения. `/trees/` — закрытая админка проекта для создателя/управляющего семейными деревьями; это не пользовательская форма создания личного древа.
- Вход, выход и смена аккаунта доступны в соответствующих семейном и личном сценариях. «Запомнить меня» сохраняет выбранный вход и email; семейный пароль и личная сессия разделены. При закрытии личного окна аккаунта клавиатурный фокус возвращается на вызвавшую его кнопку.
- Управляющие функции ограничены явным серверным allowlist. Семейные API требуют проверенной сессии; редактирование без сессии или при ошибке API не переключается на публичный локальный снимок. Фото выдаются через серверный endpoint с проверкой доступа.
- Для личного древа добавлены приватные отметки мест и заметки; семейные места не появляются автоматически в открытой карте. Разрешённые метки на карте используют только проверенные place ID и тип.
- Личная статистика считается по записям собственного серверного древа; если ранний предок неизвестен, фиктивная дата не подставляется. Ошибка подсчёта мест отдельного тейпа исправлена.
- Общие Motion/UI-стили, SVG-контролы, настройки темы и шаблон редактора распространены на существующие и будущие деревья. Hover-эффекты Atlas и Waydean ограничены устройствами с hover и точным указателем; клавиатурный фокус и сенсорный выбор остаются отдельными состояниями. Для семейного CSS добавлены детерминированная сборка bundle из 23 исходников и проверка их точного совпадения. В шаблоне таджвид-редактора декоративные стрелки и крестики заменены доступными SVG; отдельный SVG-размер/обводка применяются и в обычном режиме редактора. Service Worker обновляет согласованные версии и не кэширует семейные снимки и фотографии как публичные ресурсы.
- Вход защищён серверным лимитом семейных попыток и отзывом семейных сессий. Личный пароль ограничен минимумом 15 и максимумом 128 символов на клиенте и серверном пути регистрации. Создание второго личного древа ограничено сервером.
- Семейный редактор получил отдельное окно самоаттестации grant/revoke; журнал согласий хранится в закрытой схеме и доступен только серверному RPC. Администратор `super` не считается представителем семьи. Публичная сводка строится сервером только при явном флаге, совпадающем `DREWO_PRIVATE_REPO` и подтверждении GitHub, что источник приватный; в публичный ответ попадают только крупные интервалы проекта, без ID семей. Флаг по умолчанию выключен. Ручной deploy workflow больше не подменяет общий `GITHUB_REPO` и `GITHUB_TOKEN`, которые могут использовать другие Edge Functions.

## Миграции

В production-журнале чтением проверены три уже применённые Drewo-миграции: `20261124113244`, `20261124113604`, `20261124113705`. Следующие шесть миграций локально прошли synthetic PostgreSQL 16, но в production не применялись. Дополнительная ACL-миграция `20261128121945_drewo_increment_visit_service_only.sql` подготовлена позднее и пока не проверена на PostgreSQL. Применять все семь миграций только после проверенного DB backup и просмотра migration journal; отдельной hosted тестовой среды не будет:

1. `supabase/migrations/20261126_drewo_password_budget.sql` — приватный общий лимит попыток входа в семейные пароли.
2. `supabase/migrations/20261127_drewo_session_revocations.sql` — хранение отозванных семейных сессий до срока истечения.
3. `supabase/migrations/20261127120000_drewo_plus_one_tree_once.sql` — запрет второго личного древа и удаления строки древа через API.
4. `supabase/migrations/20261127183522_drewo_plus_person_places.sql` — приватные места людей личного древа.
5. `supabase/migrations/20261127202119_drewo_aggregate_consent.sql` — журнал grant/revoke без имён, ролевая проверка и server-only RPC.
